## 一、句式库

都是从原文里抽象出来的结构。**换掉里面的技术名词，别换掉句子的骨架**。

### 1. 冷开场（第一句）

不打招呼、不讲意义，直接交代"什么场景 / 遇到什么"。

```
模板：{做什么事}，{为什么}。
模板：{某项目}，在{环境}下{做什么}。
模板：有时，{现象}，导致{后果}。
模板：遇到个问题，{现象}：{具体表现}。如下图：
模板：{某个需求}，记录{做什么}的过程。
```

> 不使用插件，通过CSS设置滚动条样式。
> 项目中有使用到视频融合，记录实现过程。
> 某项目，在内网的统信（Linux）系统下安装neo4j。
> 有时，文字很长，从展示的地方溢出，导致UI上看着很乱。
> 遇到个问题，二维样式在三维下，显示异常：显示不全，样式随地图拖拽会闪烁、变化。

### 2. 需求陈述（背景节）

主语常省略，动词开头。

```
模板：需求是{做什么}。
模板：要求是{把 A 变成 B}。
模板：{时间/场景}，{遇到的问题}，所以{做了什么}。
模板：{旧做法}。{新问题}，所以{新做法}。
```

> 要求是把后台接口返回的数据格式转化成与echart对接的数据格式，如图：
> 以前构建部署，都是手工操作。先在本机编译打包，然后拷贝到服务器上做部署。
> 频繁的构建部署，费时烦心，所以学习使用Jenkins来实现自动化。

### 3. 诊断句（无主语，直给结论）

原因和现象都**不带"这是因为""我们发现"**。

```
模板：受到{因素}影响，导致{后果}。
模板：{排查动作}，发现是{原因}。
模板：{原因}，所以{现象}。
```

> 受到高程影响，导致部分面要素被遮盖。
> 写测试页面调试，发现是GeoJSON数据中带有z值, 且均为0。
> neo4j默认不开启ip地址监听，所以别的服务器访问不了neo4j的页面。

### 4. 方案罗列（法一 / 法二 / 法三）

有多个解法时，直接编号列，**不比较优劣除非用户问了**。

```
模板：法一：{做法}。
模板：法二：{做法}。
```

> 法一：数据上处理，把z值都过滤掉。
> 法二：设置GeoJSONLayer的`elevationInfo.mode`属性为`on-the-ground`。
> 法三：设置GeoJSONLayer的`hasZ`属性为`false`。

### 5. 先破后立（方案类必用）

先把笨写法摊开，**再逐步加需求让它烂掉**，最后给解法。

```
模板：
（第一版代码）
新增需求，{加什么}。
（第二版代码：开始变乱）
继续新增需求，{再加什么}。
（第三版代码：明显烂了）
这样整个函数就会越来越难以维护。
```

> 新增需求，在分析时增加loading。
> 这时候，loading和业务代码就已经耦合了。
> 继续新增需求，在分析前要矫正参数，在分析后要过滤结果。
> 这样整个函数就会越来越难以维护。

**为什么有效**：读者是先点头再看到解法的。少了这一步，解法就只是"另一段代码"。

### 6. 参数说明（备忘速记专用）

冒号结尾，`+` 列表，参数名反引号包住，全角破折号，句号结尾。

```
参数说明：

+ `参数名`— 说明.
+ `参数名：取值`— 说明.
```

> + `text-overflow`— 规定当文本溢出包含元素时发生的事情.
> + `background-clip`— 规定背景的绘制区域.
> + `border`— 控制外环大小和颜色.

### 7. 省略句（承认不展开）

不硬撑篇幅，直接说这里不讲。

```
模板：{某部分}，不细说。
模板：这里主要记录{范围}。
模板：{某部分}写到代码注释中。
```

> Jenkins 是基于 Java 的独立程序，所以需要Java环境，这里不细说。
> 这里主要记录如何发布一个包到npm上。
> 参数说明写到了代码注释中。

### 8. 结束语（可选，1–3 句）

只说一个实在的结论或体会。**47 篇里只有 4 篇写了收尾节**，所以默认不写。

```
模板：{方案}在{场景}上，{评价}，{评价}。
模板：{做这件事得花多少成本}。{之后会怎样}。
模板：{范围}，上面的操作就够用了。
```

> ramda在进行数据处理、数据转换上，流程似乎更加明晰，代码更加可读。
> 配置一次项目自动构建大概需要大半天时间。然后后面就不怎么用管它了。
> ramda的写法明显要更复杂一些。
> 解析服务数据，上面的操作就够用了。

模板：{动作}后，文件夹内容为：

## 二、代码块引导句对照表

原文里代码块前的句子，绝大多数 **2–15 字 + `：`**。

| ❌ 不要写 | ✅ 写成 |
|---|---|
| 接下来我为大家展示一段示例代码 | 请求示例： |
| 下面让我们来看一下具体的实现方式 | 代码如下： |
| 首先需要在配置文件中添加如下内容 | 在nginx配置中增加： |
| 解压完成之后，我们可以看到文件夹的内容如下所示 | 解压后，文件夹内容为： |
| 我们需要在代码中对 symbol 进行设置 | 代码中symbol设置： |
| 这里把完整的脚本粘贴出来供大家参考 | 粘贴文本： |
| 启动服务的方式如下 | 启动： |
| 最终的解决方案是修改这个属性 | 设置`FeatureLayer`的`elevationInfo`属性： |
| 修改之后的结果如图所示 | 修改后： |
| 排查了以下可能的原因 | 排查： |
| 这是 LayerTree 组件的实现代码 | `LayerTree.jsx`： |
| 这段代码展示了主题的定制方式 | 示例核心代码： |
| 下面展示一些微件开发的源码 | 下面是一些微件开发源码示例： |

**规律**：动词或名词开头，**不要"我们"、不要"接下来"、不要"可以看到"**，末尾一个冒号收住。

**写文档时优先用文件路径当引导句**（`` `src/layout/index.js`： ``）。读者要的是"这段代码在哪个文件里"，路径比描述有用得多。

**代码块后面**：默认不加解释。要解释就走三条路：`参数说明：` 列表、代码里的中文注释、或者（仅限设计文档）补一句机制说明。

**运行结果不要贴原始输出**，用一句话下判断：

| ❌ 不要写 | ✅ 写成 |
|---|---|
| 执行 `java --version` 后输出如下：openjdk version "17.0.1"… | 输出OpenJDK的信息。 |
| 刷新页面可以看到请求依次打到了 8080 和 8082 | F5刷新页面，会依次地访问到8080和8082上的Tomcat |
| 经测试，文件可以正常浏览、导出、写入和删除 | 能浏览、拷出、写入、删除。 |
| 报错信息为 XXX，地图没有显示出来 | 结果：无报错，不上图。 |

## 三、词表

### 爱用

| 类型 | 词 | 用法 |
|---|---|---|
| 连接/顺承 | 所以、然后、但是、同时 | 大白话连接，不用"因此""然而""此外" |
| 不确定性 | 似乎、大概、可能、大致 | **只用于技术判断**（"流程似乎更加明晰"） |
| 限定 | 这里、主要、简单 | "这里主要记录""简单介绍下"，降低承诺 |
| 动作 | 记录、整理、排查、调试、设置、添加、修改、拷贝、贴 | 动词开头，主语省略 |
| 强调 | 明显、直接、刚好 | "刚好可以使用上""明显要更复杂一些" |
| 场景 | 某项目、内网、统信、以前、有时、前段时间 | 交代场景的名词短语 |

### 慎用 / 不写

| 类型 | 例子 | 为什么 |
|---|---|---|
| **`——` 破折号** | —— | **全库零次**。想用破折号的地方直接断成两句 |
| **`……` 省略号** | ……、… | **全库零次**。话没说完就说完 |
| 引号 | `""`、`「」` | 零次。要引用就上 `>` 引用块 |
| 开场套话 | 大家好、今天我们来聊聊、众所周知、随着……的发展 | 全库零出现 |
| 结尾套话 | 希望对你有帮助、欢迎留言讨论、如有错误请指正、感谢阅读、综上所述 | 全库零出现 |
| 过渡套话 | 接下来、下面让我们、首先我们来看、值得一提的是、不难发现 | 冗余。直接给下一块内容就行 |
| 书面连接词 | 因此、然而、此外、综上所述、基于此、由于 | 换成"所以""但是""同时"或直接省略（`因此`/`然而` 零次，`由于` 只有 1 次） |
| 人称 | 大家、笔者、咱们、你们 | 全库零出现 |
| 设问 | ……呢？ | 全库只有 1 个问号。不要写设问句开场 |
| 网络热词/梗 | yyds、绝绝子、栓Q、蚌埠住了 | 破坏技术文章的可信度。【狗头】这类文字颜文字五年只用了一次 |
| 感叹号 | ！ | 自己写的一个都没有 |
| emoji | 😂🎉✅ | 零次 |
| 项目符号 `*` | `* xxx` | 零次。只用 `-`、`+`、`1.` |
| 自我吹捧 | 这个方案非常优雅、性能提升巨大 | 有代价就说代价，没数据就别夸 |
| 空洞程度副词 | 极大地、非常、十分、相当 | 换成具体事实或删掉 |
| 对冲观点 | 我个人觉得……可能会…… | 观点句直接断言。`可能` 只用于技术不确定性 |

### 那个唯一的高频小词：下面

`下面` 出现 23 次，是他最顺手的过渡词。需要引出接下来要讲的东西时，**用"下面"，不要用"接下来""下面让我们"**：

> 下面列两种CSS处理文字溢出的方式，分别针对单行文字和多行文字。
> 下面列出一道试题：
> 下面介绍两种操作系统下的安装部署。
> 下面以处理跨域来举例。
> 下面我简单介绍下流程。

注意：**"下面"后面直接跟动词**（列 / 介绍 / 以……来举例 / 我简单介绍下），不加"让我们"。

### 允许的"人味"（少量）

- 白话吐槽：`频繁的构建部署，费时烦心`
- 比喻：`在服务器上放了一个"金老头"`
- 儿化：`存一份儿`、`好看些`
- 自嘲：`整理记录一下，下次需要写的时候，就直接凑7文件了【狗头】。`
- 承认缺陷：`ramda的写法明显要更复杂一些。`

**整篇有一处就够。** 硬塞笑话比没有笑话更糟。

### 排版细节

`SKILL.md` 只留了硬禁令，这里是可以查的其余约定：

| 规则 | 说明 |
|---|---|
| 列表符号 | 一律 `-`（`+` 是 2020 年的旧习惯，2023 年后归零）。`参数说明` 那类沿用 `+` 也行，但一篇里别混 |
| 表格 | **极少**。66 篇里只有 4 篇有表格。列 API 或参数对照时才用 |
| 箭头 | 表示流程两种都用过，**别统一**：`git拉取->npm打包->替换部署文件`、`矫正参数=》分析=》过滤结果` |
| 数字 | 半角：`4.16`、`3px`、`win10`、`v20` |
| 代码块语言 | `shell`/`bash`、`js`、`jsx`、`tsx`、`css`、`json`、`plain`。目录树用 `plain` 或 `text` |
| 命令提示符 | shell 块里保留 `$`：`$ pnpm dlx @geodaoyu/chu-cli@latest create` |
| 分号 `；` | 很少用（博客 4 次、文档 3 次）。基本只出现在"默认……；无须……"这种对照句里 |
| 引号 | 用直角 ASCII `"`，不用 `""` 或 `「」`：`> 我们约定view的domId为"view"。` |
| CJK 与拉丁之间 | 空格**可有可无**，他自己也不统一（不加的情况略多）。不用刻意统一 |

## 四、标题写法

全库 125 个二级标题，105 个是独一份的。

### 高频骨架词（确实合适才用）

| 标题 | 次数 | 什么时候用 |
|---|---|---|
| 背景 | 11 | 需要交代场景和动机时的默认开头 |
| 步骤 | 3 | 教程类的分步 |
| 过程 | 3 | 按时间顺序记录 |
| 附件 | 3 | 完整代码太长，挪到文末 |
| 代码 | 2 | 备忘速记的主体 |
| 结束语 | 2 | 有实在体会要说 |
| 准备工作 / 环境 / 目录结构 | 各 1–2 | 教程类前置 |

### 写具体内容的标题（更常见）

> ## WMTSLayer加载失败
> ## 配置wss
> ## 拦截器类：MsgInterceptor.java
> ## 依赖：pom.xml
> ## 生成密钥
> ## 安装Docker
> ## 坑

**规律**：
- 直接写这一步在做什么，或者这个问题的名字。
- 涉及具体文件时用 `名字：文件名` 格式。
- `## 坑` 是一个独立的、很实用的节，装那些"不写会被坑"的点。
- 长流程用数字编号：`## 1 环境准备` → `### 3.1 端口号` → `#### 3.3.1 源码管理`。

### 不要用

`## 问题分析`、`## 解决方案`、`## 总结与展望`、`## 引言`、`## 概述`、`## 心得体会`，这些是模板词，不是内容。

## 五、常见跑偏与纠正

| 跑偏 | 症状 | 纠正 |
|---|---|---|
| **写成教程体** | 满篇"我们接下来要实现的是……" | 砍掉"我们"，砍掉"接下来"，一句话说清就换行给代码 |
| **段落太长** | 出现 3 句以上的连续段落 | 拆。中位数是 1 句 |
| **散文压过代码** | 解释了一大段，代码只有五行 | 把解释变成代码里的中文注释，或者干脆删掉，原文代码占七成 |
| **加了总结节** | 结尾"综上所述，本文介绍了……" | 删。直接停在最后一步 |
| **过度礼貌** | "希望这篇文章能帮到你" | 删。全库零出现 |
| **标题套模板** | "问题分析/解决方案" | 换成这篇文章的实际内容 |
| **编造细节** | 写了个没问过的版本号或报错文本 | 改成 `<占位>` 或去问用户。这是硬红线 |
| **假装完美** | 只给最终答案，不提弯路和代价 | 补上试错过程；有代价就写代价 |
| **用力过猛的人味** | 每段都想抖个机灵 | 整篇留一处就够，删掉其余的 |
| **堆砌连接词** | "因此……然而……此外……" | 换成"所以""但是"，或者直接省略主语接着写 |
